
# 1 Motivation 

• Ziel: Analyse von Problemen in laufender Software
    • Aufdeckung von Programmierfehlern (Bugs)
    • Aufdeckung von Konfigurationsfehlern
    • Aufdeckung von Missbrauch (Hacker-Angriffe)
• Strategie: Tracing
    • Ausgabe von Meldungen, aus denen der Programmablauf ersichtlich Wird
    • Fokus auf Operationen, die kritisch für den Erfolg sind und scheitern können
    • Ressourcen, die nicht verfügbar sind (Dateien, entfernte Systeme, Speicher)

# 2 Herausforderungen 

- Verfügbarkeit
    - Nutzer kann i.d.R. nicht auf Standard-Ausgabe der Software zugreifen (Betriebssystemkern, Dienste im Hintergrund)
- Informationsüberflutung
    - Nutzer kann in der Menge von Lognachrichten nicht die relevanten Zeilen entdecken 
- Speicherplatz
    - Festplatte läuft mit Lognachrichten voll, log 太多, 没有speicherplatz 

# 3 Strategien 

• Loglevel: jede Nachricht bekommt eine "Wichtigkeitll
    • üblich: Fehler, Warnungen, Ablaufinformation, Debug-Ausgaben
• Log-Quelle: Programme/Programmteile melden, dass sie die Quelle sind
    • Filterung von Lognachrichten, wenn man eine Quelle als Problemursache vermutet
• dynamische Konfigurierbarkeit
    • Programme enthalten alle möglichen Lognachrichten, von denen aber dynamisch entschieden wird, 0b sie aktuell benötigt werden
• Zentralisierung: alle Quellen melden Lognachrichten an die gleiche Stelle
    • lokal: einheitliche Verzeichnisse (/var/log)
    • im Netz: zentrale Logserver
• Logrotation: alte Lognachrichten werden periodisch gelöscht

• LOG_EMERG: Notfall, das System ist unbrauchbar
• LOG_ALERT: sofortige Reaktion erforderlich

# 6 dmesg

The dmesg command is used in Linux to display messages from the kernel ring buffer. This buffer contains messages generated by the kernel, typically related to hardware, drivers, and system events.

Purpose and Usage
1. **View Kernel Messages:**
    - Useful for troubleshooting hardware, drivers, and boot-related issues.
    - Displays messages like device initialization, errors, warnings, and system information.
2. **Debugging:**
    - Developers and system administrators use `dmesg` to diagnose issues like:
        - Disk errors
        - USB device detection
        - Network interface status
3. **System Boot Analysis:**
    - You can analyze kernel messages during system boot to understand hardware detection and initialization processes.

• Der Linux-Kernel hat einen Ringpuffer für Meldungen
    • Meldungen gehen auch auf die Konsole, aber: Konsole ist u.U. für Administrator nicht einsehbar, Oder Meldungen werden übersehen
    • Meldungen in Dateien zu schreiben ist nicht zuverlässig, weil ggf. das Dateisystem nicht funktioniert (z.B. read-only ist)
• dmesg liest den Ringpuffer aus
• syslogd liest den Ringpuffer ebenfalls aus


# 7 Logrotation

logrotation 不是直接删除原log 文件, 而是  将 alt log datei 改变名字 

• Problem: an Log-Dateien Wird immer hinten angehängt. Es ist nicht möglich, am Anfang der Datei Daten zu löschen (ohne die gesamte Datei zu kopieren)
• Lösung: Log-Dateien werden regelmäßig abgeschlossen und umbenannt
    • z.B. mail.log zu mail.log.l
        • die alte Datei mail.log.l musste vorher in mail.log.2 umbenannt werden»


Logrotation: Varianten
- Wann soll eine neue Logdatei angefangen werden?
    - regelmäßig, z.B. jeden Tag
    - wenn die Logdatei eine bestimmte GröBe erreicht
- Wie viele Logdateien sollen aufgehoben werden?  How many log files should be retained 
- Sollen Logdateien komprimiert werden? 压缩
    - viele Logdateien enthalten Sich immer wiederholenden Text und können sehr gut komprimiert werden

Linux logrotate
• Konfigurationsdatei /etc/logrotate.conf
```
weekly
rotate 4
create
include /etc/logrotate.d
/var/log/wtmp {
    monthly
    minsize 1M
    create 0664 root utmp
    rotate 1
}
```

This is a configuration snippet for logrotate, a tool used to manage and rotate log files on Linux systems. Let's break it down:

Explanation of the Configuration
1. **Global Options:**
    - `weekly`:  
        Log files are rotated once a week. This is the default frequency unless overridden for specific logs.
    - `rotate 4`:  
        Up to 4 rotated log files are retained. Older files beyond this number are deleted.
    - `create`:  
        After rotating a log file, a new log file is created with default permissions.
2. **Include Other Configurations:**
    - `include /etc/logrotate.d`:  
        This includes additional log rotation rules defined in individual files within `/etc/logrotate.d/`.
3. **Specific Configuration for `/var/log/wtmp`:**
    - `monthly`:  
        The `/var/log/wtmp` file is rotated monthly.
    - `minsize 1M`:  
        The log file is only rotated if it reaches a size of at least 1 MB.
    - `create 0664 root utmp`:  
        A new log file is created after rotation with permissions `0664`, owned by the user `root` and the group `utmp`.
    - `rotate 1`:  
        Only one archived log file is kept. The older file is deleted during the next rotation.

Summary of Behavior:
- Most logs will be rotated weekly, with up to 4 old log files retained.
- Logs in `/var/log/wtmp` will be rotated monthly, kept for only one cycle, and only if their size is at least 1 MB.
